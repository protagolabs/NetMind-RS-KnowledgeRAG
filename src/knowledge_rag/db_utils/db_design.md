## 概述

这是为了一个 RAG 系统搭建的数据库部分，这个 RAG 系统实现的内容是：
- 我会存入很多的文档
- 每个文档都会进行处理，对每个文档进行总结，和一些关键词提取。然后把我组合的内容，embedding成向量，并且存到向量数据库中。
- 然后会针对每个文档进行进行 chunk 处理，
    - 给每个文档在建立单独的 MySQL DB 里的 Schema，和对应的 Milvus 的 collection
    - 这里创建的部分，用来储存每个 doc 里面所有的 chunk 处理后的结果。


## 搜索逻辑

1. 给出一个 input ，通过 LLM 生成多个 query，有的是句子类型的 query，有的是关键词。然后利用这两个东西去文档级别的数据库进行 关键词匹配、向量相似度搜索。然后得到都有哪些文档和这个 input 是有关的。
2. 针对每一个匹配到的文档，我们再并行的对每一个文档进行搜索，再生成一些 query，然后用 关键词匹配和向量相似度进行搜索，拿到大量的数据。

说明：
- 你不需要管 query 是怎生成的，那是另外的部分，你只需要准备对应的函数，输入query、关键词匹配或者向量相似度计算的字段是什么，都独立成一个个functions
- 每个数据库、schema、什么的 我都还没设计好，所以你要尽可能的灵活，或者方便之后改进。
- 无论我搜索的是关键词还是向量相似度，我拿到的都是 MySQL 里的具体一整条数据。我如何利用 你暂时也不需要考虑，那是另外的部分。
